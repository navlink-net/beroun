# App store, signing and releases

API: `docs/system-api.md`, "The store".

## Pieces

| Piece | Where | Role |
| --- | --- | --- |
| Catalog and arbiter | `snc-arbiter` (`tunnel_cat` repository), platform `beroun`; sites apps.navlink.net / navlink.net | Receives packages, checks them, signs at approval, serves `?os=beroun` |
| System side | `runtime/appinstall.py`, `store_*` in `shelld.py` | Download, verify, install, update, remove with rollback |
| Store app | `apps/store` (system app, `apps.manage`, `Network` required) | List with filters All/Installed/Updates, a card with *what it asks for*, Install/Update/Remove |
| Packaging | `scripts/beroun-pack.py`, `scripts/beroun-publish.sh` | Build packages of OS Beroun's own apps from git HEAD and publish them |

## A package

A zip from the store: the app folder with `manifest.json` at the root plus `sign.list` added by the arbiter at approval (`<path>: <sha256>` lines sorted by path, then `---SIGNATURE---` and a base64 Ed25519 signature over the lines).
The arbiter's key is made once by the operator (never generated by the arbiter); its public half is built into OS Beroun (`appinstall.STORE_PUBLIC_KEY`, override `INTELLICAT_BEROUN_PUBKEY`).

Rules (checked by the arbiter and again by the system, `appinstall.package_errors`): format 1; the `beroun` field (minimum OS version, `manifest.BEROUN_VERSION`) required; no `native`; no `.so`/`.dll`/ELF/PE/Mach-O; `python3` the only program; `module` and
`privileged` services refused; no links or `..`; size limits; service ports 49000–49999; only the `caroline.ask` permission; no A2A exposure of agents yet; `system` must equal whether the id is a system app (only a platform admin may publish one);
`required` capabilities are checked against the target (the reference device offers Notification, FileStorage, Network, Microphone, ExternalDisplay, WebGL; `DEVICE_CAPABILITIES`). The list of capability names is open: the arbiter checks only the form of a name, and a name the device does not know is a capability the device lacks.

## Install, update, remove

* **Install/update** (`POST /api/store/install {app}`): download only from `INTELLICAT_STORE_ASSETS`; check the store's sha256, the signature against the built-in key, every file hash (`sign.list` must name exactly the files of the zip), the rules and the manifest; never a downgrade (`not-higher`); a service id or port of another app is refused (`conflict`). The new folder is built beside the old one; **a failure puts the previous state back**, a crash mid-way is repaired at the next start. The app is on the launcher at once; its services, endpoints, agents, permissions, big page and Caroline's tools appear without a restart and return at start.
* **Remove**: a store app is closed, its services stopped, everything it registered undone, and its folder, data (`<data>/apps/<id>/`) and saved place deleted; files it wrote to the storage card stay. A *preinstalled* app is hidden and **keeps its data**; installing it again restores it from the firmware without a download. A *system* app is only updated.
* **Automatic updates**: setting `auto_update` (Settings; on by default). A minute after start and every 6 hours the shell installs waiting updates, except one that asks for more rights than the installed version or whose app is open; a notification names each. The Store tile shows a badge with the number of waiting updates.
* Error codes: `offline` 502, `not-found`/`not-installed` 404, `system` 403, `conflict`/`not-higher`/`missing-capability` 409, `bad-signature` 422, `no-key` 503. Only the Store page and Caroline may call `/api/store/*`.

## Publishing OS Beroun's own apps

```bash
scripts/beroun-pack.py OUT_DIR [app ...]            # packages from git HEAD, never the working tree
ARBITER=https://navlink.net ADMIN_TOKEN=... scripts/beroun-publish.sh OUT_DIR [id ...]
```

`beroun-pack.py` writes `<id>-<version>.zip` plus a `.json` listing (name, description, category, icon path), adds the `beroun` field when missing, and refuses a package that breaks the rules. `beroun-publish.sh` posts to the arbiter's
`/api/admin/beroun/publish` (token from the environment only; an already-published version is refused). To ship a new version of a firmware app: raise its manifest `version`, commit, pack, publish.
Published at the firmware's versions: Music, Video, Calculator, Notepad, Files, Communicator, Knights & Ladies, Pirates, Quidditch, Settings, Wi-Fi. **Stay with the firmware** (rules not loosened): Browser (native), Calendar and Clock (system-owned ports), Ratatosk (module service), Store (`apps.manage`); `ext-a`/`ext-b` are hidden tests.

## Versions and releases

* The OS version is `INTELLICAT_VERSION` in `config/versions.env` (1.0; the name predates the OS/device split). Settings > About and `GET /api/about` show it. Apps state the minimum OS they need in `beroun`.
* No release process for a firmware image exists yet. Pinning Weston and WPE in `versions.env` is the contract an image must follow.
* Caroline reaches every target through her own signed release (`release.json`, platform `beroun`; see [CAROLINE.md](CAROLINE.md)). The pinned submodule is the baseline.
* Tests: `appinstall_test.py` (74 checks, packages signed by the arbiter's own Go code), `store_shell_test.py` (45, the real shell with a stand-in arbiter), `store_e2e.py` (24, a real private simulator plus the arbiter's real code, driven by the console's buttons).
