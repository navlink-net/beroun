# The format of an app

Every app of the console, and every view of the system itself, is described by **one manifest** of our own (format 1). The shell reads it (`runtime/manifest.py`),
refuses what does not fit, and `tests/manifest_test.py` checks all of them.

* An **app** is `apps/<id>/manifest.json` (served at `/apps/<id>/...`).
* A **view of the system** (Caroline: her chat layer, her voice view, her wizard) is `system/<id>/view.json` (served at `/system/<id>/...`): the same format.
  Caroline is not an app; she is part of the firmware and must never be put in `apps/`.

```json
{
  "format": 1,
  "id": "notepad",
  "name": "Notepad",
  "version": "1.1.0",
  "icon": "icon.svg",
  "frontend": {"entry": "index.html", "window": "shared"},
  "state": true,
  "opens": ["txt"],
  "tile": {"order": 20},
  "services": [],
  "caroline": {
    "description": "Plain-text notes: read, write and open the note on the screen",
    "skills": ["skills"],
    "tools": [{"name": "get_text", "description": "The text of the open note", "input": {}}]
  }
}
```

| Field | Meaning |
| --- | --- |
| `format` | always `1` |
| `id`, `name`, `version`, `icon` | the folder name (lowercase, digits, `-`), the title on the tile, `x.y.z`, the tile's picture (an app with a tile needs one) |
| `frontend` | a web page: `entry` (a file of the app's folder) **or** `url` (a page of another origin); `window`: `shared` (a page of the launcher's cog, one frontend at a time) or `own` (a `cog` of its own, the default); `microphone`, `transparent` |
| `native` | instead of `frontend`: `{"cmd": [...]}`, a program of its own (`{port}`, `{sim}` are filled in); exactly one of `frontend` and `native` |
| `tile` | the launcher: `order` (smaller is earlier), `hidden` (launched by the system, no tile) |
| `state` | **the contract**: the app saves its place when it is closed and comes back to it (`Platform.state`, `Platform.onClose`). A frontend in the shared window must have `"state": true`, and its page must use `Platform.state` (checked) |
| `opens` | the file types (extensions) the app opens when the file manager chooses one |
| `services` | the backends that survive the close of the app ([SHELL_DAEMON.md](SHELL_DAEMON.md#services), "Services"): `host`, `start`, `priority`, `memory_mb`, `sleep`, `takeover`, ... `host` is `module` (an object of `shelld`'s code), `process` (`cmd`, started and watched by the manager) or `child` (a process that **another service starts**, found among the descendants of its `parent` by `match`: `argv`, a string or a list of texts the command line holds, and `env`, texts the environment values hold). A child is listed, measured and budgeted on its own and its parent's figure is without it; it is **not stoppable** by the manager (its parent's code starts and stops it), so it is never a victim of the memory limit. The Communicator declares WhatsApp's sidecar and `signal-cli` of both accounts this way (`apps/communicator/manifest.json`) |
| `endpoints` | what the shell passes on to a service of the app: `{"path": "alarms", "methods": ["GET", "POST"], "service": "alarmd", "access": ["page", "mcp"]}`. `GET/POST /api/app/<id>/<path>` goes to `127.0.0.1:<port>/<path>` of the service, which then needs a `port` (a process service; `{port}` in its `cmd` and `INTELLICAT_SERVICE_PORT` are filled in, `{app}` is the app's folder). Only the app's own page (`page`), its MCP servers (`mcp`, header `X-IntelliCat-Mcp: <id>`) and the shell on behalf of its agents (`agent`, the endpoint an agent's `host` names) may call; the service is started if it is not running. The Clock (`alarmd`, rings in sleep and takes over the window) and the Calendar (`calendard`) are the examples |
| `caroline` | **how Caroline drives the app**; the app becomes the tool group `app-<id>` of hers. `description` (required): one line for her list of groups. `skills`: folders of the app (a skill, i.e. a folder with a `SKILL.md`, or a folder of skills) that join her skill catalog. `mcp`: MCP servers of the app, `{"id", "transport": "stdio", "cmd": [...]}` (`{app}` is the app's folder, `{port}` the shell's port) or `{"id", "transport": "http", "url"}`, optionally `env` and `service` (one of the app's `services`, started like on opening the app). `tools`: tools of the page, `{"name", "description", "input": {param: "string" \| "number" \| "integer" \| "boolean"}}` (a type ending in `?`, e.g. `"string?"`, is an optional parameter), answered by the page with `Platform.tools.handle(name, fn)` (the app is opened first when Caroline calls one). An app without the section is still reachable by her through OS Beroun's own group (`beroun_*`) |
| `agents` | **the autonomous agents the app publishes for Caroline** ([architecture.md](architecture.md)); a list of `{"id", "description", "skills", "host", "camerlengo", "permissions"}`. The manifest is the approval: what an agent declares is what it may do, and nobody clicks anything. `description` (required): one line telling Caroline what the agent is for. `skills` (at least one): `{"name", "description", "input": {param: type}, "output": "text" \| "json", "long", "confirm"}`; `input` has the types of `caroline.tools`; `long: true` marks a skill expected to take more than a few seconds (run as a task Caroline can poll and cancel); `confirm: true` marks an effect outside the app, a hint Caroline weighs by her own policy. `host` says where the agent answers, exactly one of: `{"service": "<id>", "endpoint": "<path>"}` (a service of the app and one of its `endpoints` whose `access` includes `agent`), `{"mcp": "<id>"}` (a server of `caroline.mcp`), `{"page": true}` (the app's page, over `/appws`). `camerlengo`: the Camerlengo API commands the agent may call through the shell, charged to the owner's wallet, `"ai:stt"` or a family `"email:*"`; absent = none. `permissions`: names from `manifest.PERMISSIONS` (`files.read`, `files.write`, `net.status`, `net.manage`, `settings.read`, `settings.write`, `notifications.read`, `notifications.post`, `sound`, `vibration`, `message_box`, `apps.open`), what of the system the agent may use beyond its own app's data; absent = none. `host` may also be `{"a2a": "<card url>", "key"?: "<name>"}`: a REMOTE A2A agent (A2A 1.0 over JSON-RPC) that Caroline commands like any other; its `skills` may be left out (they come from its card), it has no `camerlengo` and no `permissions` and cannot be exposed again; `key` is the NAME of a key kept in the device's `a2a-keys.json`, never the key itself; what Caroline gives such an agent leaves the device. `a2a`: `{"expose": true \| false, "confirm"?: bool, "tags"?: [text]}`; with `expose: true` the agent is reachable from outside as an A2A agent (an Agent Card and the JSON-RPC calls of A2A 1.0 on the shell's A2A listener, `Authorization: Bearer <the key of the device>`); the skills marked `confirm` are NOT offered outside unless `a2a.confirm` is true; an agent whose every skill is marked `confirm` cannot be exposed without it; no port, key or address is ever written in a manifest. How the agent solves a task is its own business: the format has no model field. The broker, Caroline's `agents` group, the calls of Camerlengo, the owner's view and the A2A listener read it at run time |
| `external` | **a page for the external (HDMI) screen** ([system-api.md](system-api.md)): `{"entry": "big.html", "state": true}`, or `{"url": ..., "state": true}` for a native app (`{port}` is filled in). The app has two pages: the page of the console (`frontend`, the remote) and this big page. `state` must be `true` (the big page is covered by another app and comes back to the same place: it keeps its place in `Platform.state`, and `entry` is checked to use it). The app uses the screen only when its page calls `Platform.display.open()`; see "The external screen" in [system-api.md](system-api.md). **`"input": "game"`** (the only value; optional) marks a game: with a screen the game goes to it by itself (`web-shell/gameext.js`, one page for both screens) and, while it is on top, owns the sticks, X and Y (no mouse), see [system-api.md](system-api.md). `{"cmd": [...], "env": {...}, "state": true}` makes the big window a **native program** of the app (the browser); with `"input": "game"` it is a game that reads the gamepad itself (the cloud Minecraft's player): while it is on top every button stays the gamepad's |
| `permissions` | **what the app itself may ask of the system**; a list of names, the manifest is the approval (declared = allowed, nobody clicks). Today three: `apps.manage` (install, update and remove the apps of the store, `/api/store/*`; only the Store app declares it, a package may not); `caroline.ask`, the app (its page and its services) may send Caroline a request and get her answer, `POST /api/caroline/ask` `{text, timeout?}`; `account.session`, a **service** of the app (never its page) gets the device's SquirrelWisdom session, `GET /api/account/session[?fresh=1]` with `X-IntelliCat-Service-Id`, for a cloud service of the account that checks it (the cloud Minecraft's orchestrator). Not the agents' `permissions` (those are inside an `agents` entry) |
| `system` | **a system app of OS Beroun** (`true`; Browser, Settings, Ratatosk, Wi-Fi and the Store itself are): the store can only **update** it, never remove it and never install one that is not on the device. An app without it that comes with the firmware (Calculator, Notepad, the games, ...) is *preinstalled*: the store can also remove it (it is hidden, its data stays) and install it again; everything else is an app *from the store*. A package must say `"system": true` exactly when its id is a system app of the device, and only an admin of the platform can publish one |
| `beroun` | the lowest version of OS Beroun (its system API) the app needs, `x.y` or `x.y.z`; an app that needs a newer OS than the device has is refused (`manifest.BEROUN_VERSION`). A package of the app store must have it; the built-in apps may leave it out |
| `capabilities` | **what of the device the app uses**: `[{"name", "scope"}]`, the contract of CATalogue (`TunnelCat/CATalogue/APPSTORE_PLAN.md`, "Manifest as a real capability contract"). `name` is **an open list**: any name of the form capital letter, then letters and digits, 2 to 32 characters (`runtime/manifest.py` `CAPABILITY_NAME`; the arbiter checks the same form), each once. The names this OS knows are `Camera`, `Microphone`, `GPS`, `Bluetooth`, `NFC`, `Notification`, `FileStorage`, `CloudStorage`, `Network`, `ExternalDisplay` and `WebGL` (the last two are ours; `WebGL`: the page can make a WebGL context, for 3D); a new capability is added to the device only, with no change of the arbiter, and a package that names one this OS does not know still installs (the device lacks it: an optional one is absent, a required one is `missing-capability`). What is not declared is not given; a declared one the device lacks is simply absent and the app does without it. `scope` is open per capability; **`"scope": {"required": true}`** (our addition) says the app does not work without it, and the store does not offer it on a device that lacks it (`manifest.required_capabilities`). `Microphone` is the app's ask for the microphone (a view of the system says `frontend.microphone`). `permissions` and the agents' `permissions` are another thing: access to the system and to Caroline, not to hardware |
| `binaries` | **the native parts of a package**: `{name: {target: path}}`, the target one of `linux-arm64`, `linux-x86_64`, `android-arm64`, `android-x86_64` and the path `bin/<target>/<file>`. A command (`services[].cmd`, `caroline.mcp[].cmd`, `external.cmd`) starts one as `{bin:name}`; `shelld` fills in the file of this device's target (`manifest.device_target()`), and a service whose binary has no build for the target is left out. Every `{bin:name}` is declared and every binary is used. In a package a binary must be an ELF of its target's CPU, named here and in `bin/<target>/` only; the signature covers all targets, a device unpacks its own (`appinstall`), and a package with no build for the device is not offered (`missing-capability`). `scripts/beroun-pack.py` builds them from the source's `src/<name>.c` (`packages/<id>/`) |

Unknown fields are errors. The old flat manifests (`entry`, `window`, `order`, `hidden`, `microphone`, ...) are no longer read.
